# 08-04 — Đo lường theo tenant

> Yêu cầu: **PERF-04**. Spec: `superpowers/specs/2026-09-24-p8-toi-uu-tai-chi-phi-design.md`.
> Phụ thuộc: không. **Wave 1 — làm trước 08-01 và 08-02** để còn số "trước" mà so.
> Plan là hợp đồng + nghiệm thu, không phải bản nháp code. Viết bằng TDD.

**Mục tiêu:** trả lời được bằng log, không bằng phỏng đoán — quán nào tốn nhất, đường nào chậm
nhất, và **POS render bao nhiêu lần mỗi giờ cao điểm**. Con số cuối cùng là thứ quyết định có viết
lại realtime (hướng C) hay không.

**Cách làm:** log JSON có cấu trúc, một dòng mỗi request. Không thêm dịch vụ, không dựng dashboard
— log của Vercel đủ để truy vấn. Nguyên tắc: nếu phải cài thêm hạ tầng để biết mình tốn bao nhiêu
thì chi phí đo đã lớn hơn cái cần đo.

## Ràng buộc

- **Không ghi PII, không ghi nội dung đơn.** Chỉ `tenant_slug`, `path`, `ms`, `status`.
- Một dòng cho mỗi request vào `/r/*`. Không log request asset tĩnh.
- Log **không được** làm hỏng request: mọi lỗi trong đường ghi log phải bị nuốt.
- Chạy được trên Vercel Edge runtime (middleware) — không dùng API chỉ có ở Node.

## Hợp đồng

```ts
// lib/observability/log.ts
export type RequestLog = {
  evt: "req";
  tenant: string | null;   // slug, null nếu route ngoài /r/*
  path: string;            // đã bỏ query string
  ms: number;
  status: number;
};

export function logRequest(entry: RequestLog): void;   // nuốt mọi lỗi

/** Đo một thao tác server và ghi { evt: "op", name, tenant, ms }. Trả nguyên kết quả. */
export function timed<T>(name: string, tenant: string | null, fn: () => Promise<T>): Promise<T>;
```

Dạng log: **một dòng JSON** trên `stdout` (`console.log`). Không dùng `console.info/warn` — Vercel
gộp chúng khác nhau và sẽ khó lọc.

## Cạm bẫy đã biết

- **Query string có thể chứa token bàn** (`?t=<qr_token>`). Phải cắt bỏ query trước khi log, nếu
  không là ghi thẳng khóa mở bàn vào log.
- **Slug nằm ở `pathname.split("/")[2]`** — middleware đã tính sẵn (`x-tenant-slug`), dùng lại chứ
  đừng tính lại.
- Middleware chạy cho **mọi** route trừ asset tĩnh (xem `matcher` hiện tại). Đường không phải
  `/r/*` thì `tenant: null` — vẫn log, vì `/super` và `/` cũng tốn tiền.
- `timed` bọc quanh hàm đã có **không được đổi chữ ký** của chúng: `getPosSnapshot(tenantId)` và
  `getCustomerMenu(slug)` giữ nguyên để 30+ lối gọi không phải sửa.
- Đừng đo bằng `Date.now()` trong middleware Edge rồi trừ ở chỗ khác — dùng một mốc duy nhất trong
  cùng scope.

## Test phải có

`tests/observability/log.test.ts`:

- `logRequest` in **đúng một dòng**, parse được bằng `JSON.parse`, đủ 5 trường.
- `logRequest` **cắt query string**: path `/r/pho-viet/menu?t=abc123` → log `/r/pho-viet/menu`,
  và chuỗi `abc123` **không xuất hiện** trong dòng log.
- `logRequest` nuốt lỗi: giả lập `console.log` ném → hàm không ném ra ngoài.
- `timed` trả **đúng** giá trị của `fn`, và ghi `ms` ≥ thời gian thật của `fn` (dùng `fn` ngủ 20ms).
- `timed` khi `fn` ném: vẫn ghi log rồi **ném tiếp** (không nuốt lỗi nghiệp vụ).
